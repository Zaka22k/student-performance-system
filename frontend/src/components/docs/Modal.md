# Modal

Модальное окно поверх страницы: затемнённый фон с размытием, окно по центру (на мобильных экранах `max-width: 768px` — на весь экран), заголовок с кнопкой закрытия, прокручиваемое тело и необязательная кнопка действия внизу. Окно рендерится через портал в `document.body`.

Есть два способа использовать его:

* **`<Modal>`** — компонент, которым вы управляете сами через `isOpen` и `onClose`.

* **`ModalProvider` + `useModal()`** — окно открывается вызовом `openModal({...})` из любого места приложения, без состояния `isOpen` в каждом компоненте.

## Подключение

```
Modal.tsx
Modal.module.css
ModalContext.tsx    // ModalProvider и useModal
Button/Button.tsx   // кнопки в заголовке и футере
icons               // CloseIcon (значок закрытия)
index.css           // должен быть подключён в приложении: токены и классы типографики
```

```tsx
import Modal from "./Modal";
import { ModalProvider, useModal } from "./ModalContext";
```

`Modal` экспортируется и как `export default`, и как именованный `Modal`.

## Быстрый старт

### Через провайдер

Оберните приложение в `ModalProvider` один раз:

```tsx
<ModalProvider>
  <App />
</ModalProvider>
```

И открывайте окна откуда угодно:

```tsx
function DeleteButton({ id }: { id: string }) {
  const { openModal } = useModal();

  return (
    <Button
      onClick={() =>
        openModal({
          title: "Удалить город?",
          content: "Это действие нельзя отменить.",
          actionText: "Удалить",
          onAction: async () => {
            await api.deleteCity(id);
          },
        })
      }
    >
      Удалить
    </Button>
  );
}
```

### Напрямую

```tsx
const [open, setOpen] = useState(false);

<Modal
  isOpen={open}
  onClose={() => setOpen(false)}
  title="Удалить город?"
  actionText="Удалить"
  onAction={() => api.deleteCity(id)}
>
  Это действие нельзя отменить.
</Modal>
```

## Свойства `Modal`

| Свойство | Тип | По умолчанию | Описание | 
| ----- | ----- | ----- | ----- | 
| `isOpen` | `boolean` | — | Открыто ли окно. Закрытие проигрывает анимацию, после неё окно убирается из DOM | 
| `onClose` | `() => void` | — | Вызывается, когда окно просит закрыться: кнопка ×, `Esc`, клик по фону, успешное действие | 
| `title` | `ReactNode` | — | Заголовок (одна строка, длинный обрезается многоточием) | 
| `children` | `ReactNode \| (props: ModalFormRenderProps) => ReactNode` | — | Содержимое: обычный JSX или функция для форм | 
| `actionText` | `string` | `"Подтвердить"` | Текст кнопки действия | 
| `actionAppearance` | `ButtonAppearance` | `"accent"` | Вид кнопки действия. Допустимые значения см. в `Button` | 
| `onAction` | `() => void \| Promise<void>` | — | Обработчик кнопки действия | 
| `onError` | `(error: unknown) => void` | — | Вызывается, если действие завершилось ошибкой (например, чтобы показать тост или отправить ошибку в лог) | 
| `errorMessage` | `ReactNode \| (error: unknown) => ReactNode` | `"Не удалось выполнить действие. Попробуйте ещё раз."` | Сообщение об ошибке в футере окна. Строка, JSX или функция, получающая ошибку | 
| `width` | `number \| string` | `480` | Ширина окна. Число — пиксели, строка — любое значение CSS. Окно не шире экрана. На экранах `<= 768px` игнорируется (всегда `100%`) | 
| `closeOnBackdropClick` | `boolean` | `true` | Закрывать ли окно кликом по затемнённому фону | 

### `ModalFormRenderProps`

Эти значения получает `children`, если это функция:

| Поле | Тип | Описание | 
| ----- | ----- | ----- | 
| `formId` | `string` | Уникальный id (`useId`). Повесьте его на `<form id={formId}>`: тогда кнопка в футере, `Enter` в полях этой формы и её отправка запускают одно и то же действие, причём сначала срабатывает браузерная проверка полей (`required` и др.) | 
| `isSubmitting` | `boolean` | `true`, пока выполняется действие. Используйте, чтобы блокировать поля | 
| `registerAction` | `(fn: () => void \| Promise<void>) => void` | Регистрирует обработчик кнопки действия со свежим состоянием формы | 

## Провайдер и хук

### `useModal()`

Возвращает:

| Метод | Описание | 
| ----- | ----- | 
| `openModal(options)` | Открывает окно. Если другое окно уже открыто, оно заменяется новым | 
| `closeModal()` | Закрывает окно и вызывает `options.onClose`, если он был передан | 

Вне `<ModalProvider>` хук бросает ошибку: `useModal должен использоваться внутри <ModalProvider>`.

### `OpenModalOptions`

Те же свойства, что у `Modal`, кроме `isOpen`, `onClose` и `children`, плюс:

| Свойство | Тип | Описание | 
| ----- | ----- | ----- | 
| `content` | `ReactNode \| (props: ModalFormRenderProps) => ReactNode` | Содержимое окна (аналог `children`) | 
| `onClose` | `() => void` | Необязательный колбэк, вызывается при любом закрытии через `closeModal` | 

`title` обязателен, остальное необязательно.

## Когда показывается кнопка действия

Футер с кнопкой появляется, если выполнено **хотя бы одно** из условий:

* передан `actionText`;

* передан `onAction`;

* содержимое — функция (форма).

Иначе окно показывает только заголовок и тело, а закрыть его можно через ×, `Esc` или клик по фону.

## Как работает кнопка действия

1. Берётся обработчик: сначала тот, что зарегистрирован через `registerAction`, иначе `onAction`.

2. Если обработчика нет, окно просто закрывается.

3. Иначе кнопка блокируется (`isSubmitting = true`), вызывается обработчик и выполняется `await`.

4. Если обработчик завершился без ошибки, вызывается `onClose` и окно закрывается.

5. Если обработчик бросил ошибку, окно **остаётся открытым**: ошибка пишется в `console.error`, вызывается `onError`, в футере слева от кнопки появляется сообщение (`errorMessage`), кнопка снова доступна. Сообщение скрывается при следующем запуске действия и при закрытии окна.

Повторный запуск, пока действие ещё выполняется, игнорируется (например, двойной `Enter` или `Enter` вместе с кликом).

Пока `isSubmitting` равен `true`, заблокированы кнопка ×, `Esc` и клик по фону, то есть окно нельзя закрыть посреди сохранения.

## Примеры

### 1. Сообщение без действия

```tsx
openModal({
  title: "Готово",
  content: "Город добавлен в список.",
});
```

### 2. Подтверждение с асинхронным действием

```tsx
openModal({
  title: "Удалить город?",
  content: "Это действие нельзя отменить.",
  actionText: "Удалить",
  onAction: async () => {
    await api.deleteCity(id);
  },
});
```

Пока идёт запрос, кнопка заблокирована. После успеха окно закроется само.

### 3. Ошибка в действии

Если обработчик бросает ошибку, окно остаётся открытым, а в футере слева от кнопки появляется сообщение. Достаточно не глотать ошибку:

```tsx
openModal({
  title: "Удалить город?",
  actionText: "Удалить",
  onAction: () => api.deleteCity(id), // отклонённый промис = ошибка
});
```

Своё сообщение: строкой, JSX или функцией от ошибки.

```tsx
openModal({
  title: "Удалить город?",
  actionText: "Удалить",
  onAction: () => api.deleteCity(id),
  errorMessage: (error) =>
    error instanceof ApiError && error.status === 409
      ? "Город используется, его нельзя удалить."
      : "Не удалось удалить город. Попробуйте ещё раз.",
});
```

Дополнительная реакция, например тост или лог, через `onError`:

```tsx
openModal({
  title: "Удалить город?",
  actionText: "Удалить",
  onAction: () => api.deleteCity(id),
  onError: (error) => logger.error("deleteCity failed", error),
});
```

Если вы перехватываете ошибку внутри `onAction` сами, пробросьте её дальше (`throw e`). Иначе окно сочтёт действие успешным и закроется.

### 4. Форма с состоянием

Состояние формы должно жить в **компоненте**, который вы возвращаете из функции. Сама функция вызывается внутри `Modal`, хуки в ней использовать нельзя.

```tsx
function CityForm({
  formId,
  isSubmitting,
  registerAction,
  onSave,
}: ModalFormRenderProps & { onSave: (data: CityData) => Promise<void> }) {
  const [name, setName] = useState("");
  const [country, setCountry] = useState("bg");

  // Обновляем обработчик при каждом изменении формы,
  // чтобы кнопка действия всегда видела свежие значения.
  useEffect(() => {
    registerAction(() => onSave({ name, country }));
  }, [registerAction, onSave, name, country]);

  return (
    <form id={formId}>
      <TextField
        label="Название:"
        value={name}
        onChange={(e) => setName(e.target.value)}
        disabled={isSubmitting}
      />
      <ComboBox
        label="Страна:"
        options={countries}
        valueKey="id"
        labelKey="name"
        value={country}
        onChange={(value) => setCountry(value)}
        disabled={isSubmitting}
      />
    </form>
  );
}

openModal({
  title: "Новый город",
  actionText: "Сохранить",
  content: (formProps) => <CityForm {...formProps} onSave={api.createCity} />,
});
```

Зарегистрированный обработчик сбрасывается при закрытии окна. После успешного `onSave` окно закроется.

Так как у формы стоит `id={formId}`, `Enter` в её текстовых полях запускает то же действие, что кнопка «Сохранить», а `onSubmit` с `preventDefault` не нужен. Страница при этом не перезагружается. Подробности в разделе «Поведение».

### 5. Своя ширина

```tsx
openModal({ title: "Подробности", content: <Details />, width: 640 });
openModal({ title: "Подробности", content: <Details />, width: "min(90vw, 720px)" });
```

### 6. Не закрывать по клику на фон

Полезно для форм, чтобы случайный клик не стёр введённые данные:

```tsx
openModal({
  title: "Новый город",
  content: (p) => <CityForm {...p} onSave={api.createCity} />,
  closeOnBackdropClick: false,
});
```

`Esc` и кнопка × при этом продолжают работать.

### 7. Колбэк при закрытии

```tsx
openModal({
  title: "Настройки",
  content: <Settings />,
  onClose: () => analytics.track("settings_closed"),
});
```

`onClose` сработает при любом закрытии: ×, `Esc`, клик по фону, успешное действие и вызов `closeModal()`.

### 8. Вид кнопки действия

```tsx
<Modal
  isOpen={open}
  onClose={close}
  title="Выйти?"
  actionAppearance="accent"
  actionText="Выйти"
  onAction={logout}
>
  Вы будете разлогинены на этом устройстве.
</Modal>
```

## Поведение

* Пока окно в DOM, прокрутка страницы блокируется (`body { overflow: hidden }`). При закрытии прежнее значение `overflow` у `body` возвращается.

* `Esc` закрывает окно, если оно открыто и не идёт сохранение. Если `Esc` уже обработал вложенный элемент (например, закрыл открытый список `ComboBox`), окно остаётся открытым: нужно нажать `Esc` ещё раз. Настройка `closeOnBackdropClick` на `Esc` не влияет.

* При открытии фокус переходит в окно, `Tab` и `Shift+Tab` ходят по кругу внутри окна. Если содержимое само взяло фокус (например, `autoFocus` на поле), окно его не перебивает. При закрытии фокус возвращается на элемент, который был в фокусе до открытия.

* `Enter` в текстовом поле формы с `id={formId}` запускает действие окна, как кнопка в футере. Если `Enter` уже обработал вложенный элемент (например, `ComboBox` выбрал пункт списка), действие не запускается. `Enter` в `textarea`, на кнопках, флажках и переключателях действие не запускает, во время ввода через IME (композиции) тоже. Отправка такой формы (например, кнопкой `type="submit"` внутри неё) тоже запускает действие, а не перезагружает страницу. Формы с другим `id` окно не трогает. Собственный `onSubmit` формы `formId` при этом вызывается только при отправке кнопкой, а не по `Enter`.

* Клик по фону закрывает окно, только если нажали именно на фон, а не на окно, и `closeOnBackdropClick` не равен `false`.

* Выпадающий список `ComboBox` внутри окна не обрезается телом окна: он рисуется отдельным слоем поверх всего (`--ZIndexPopup`, выше окна).

* При закрытии окно сначала проигрывает анимацию выхода и только по её окончании (событие `animationend`) удаляется из DOM. Если переопределить анимации в CSS на `none`, окно не размонтируется.

* Провайдер показывает одно окно за раз. Вызов `openModal`, пока другое окно открыто, подменяет его содержимое без анимации.

* Опции из `openModal` сохраняются в состоянии провайдера в момент вызова. Если `content` или `onAction` используют состояние внешнего компонента, они увидят значения на момент вызова. Для живых данных используйте компонент с собственным состоянием и `registerAction`, как в примере 4.

## Доступность

* Окно имеет `role="dialog"` и `aria-modal="true"`, а `aria-labelledby` указывает на заголовок, поэтому скринридер читает `title` как имя окна.

* Фокус переносится в окно при открытии, удерживается внутри по `Tab` и возвращается на прежний элемент при закрытии.

* У кнопки закрытия есть `aria-label="Закрыть модальное окно"`, пока идёт действие, она заблокирована.

* `Esc` закрывает окно.

## Ограничения

* **Фокус при `autoFocus`.** Если фокус в момент открытия уже внутри окна (из-за `autoFocus` в содержимом), окно не запоминает прежний элемент и не возвращает на него фокус при закрытии.

* **Действие идёт через отправку формы.** Кнопка в футере и `Enter` вызывают `form.requestSubmit()` у формы с `id={formId}`. Поэтому браузерная проверка полей (`required`, `pattern`, `minLength` и т. п.) работает: при ошибке браузер показывает подсказку у первого неверного поля, а действие не запускается. У формы с `noValidate` проверки нет. Собственный `onSubmit` на форме тоже вызывается, но отменить им действие нельзя (`preventDefault` страницу не перезагружает, а действие всё равно запускается): проверяйте данные атрибутами полей или бросайте ошибку в `registerAction`/`onAction`.

* **Без формы с `id={formId}` проверки полей нет.** Если разметка не содержит `<form id={formId}>`, кнопка в футере просто вызывает действие, и данные нужно проверять в обработчике (бросьте ошибку, чтобы показать сообщение).

* **Сообщение об ошибке одно, на всё окно.** Это одна строка (или JSX) в футере. Подсветку полей формы с ошибками делайте сами через состояние формы.

* **Тексты вшиты в код.** Подпись кнопки закрытия, `"Подтвердить"`, сообщение об ошибке по умолчанию, сообщение об ошибке `useModal` и запись в консоли написаны по-русски. Сообщение об ошибке действия можно заменить через `errorMessage`, остальные настраиваются только правкой кода.
