# DataGrid

Таблица только для просмотра для длинных списков. Строки виртуализированы (в DOM только те, что видны), ширину колонок можно менять, строки можно выделять, следующая порция данных запрашивается, когда пользователь доходит до конца списка. У строки есть контекстное меню на `GlassPanel`.

Таблица ничего не загружает, не сортирует и не фильтрует сама: данные, загрузку, ошибки, поиск и сортировку ведёт родитель. Таблица только показывает переданные `rows`.

## Подключение

```
DataGrid.tsx
DataGrid.module.css
ContextMenu/        // ContextMenu.tsx и ContextMenu.module.css, см. раздел «Контекстное меню»

ProgressRing/       // кольцо подгрузки, см. ProgressRing.md
Button/             // кнопка «Повторить»
GlassPanel.tsx      // меню строки
liquidGlass.ts      // нужен GlassPanel
index.css           // должен быть подключён в приложении: токены и классы типографики
```

```tsx
import { DataGrid } from "./DataGrid";
import type { DataGridColumn } from "./DataGrid";
```

Компонент экспортируется и как `DataGrid`, и как `export default`. Пути импортов в `DataGrid.tsx` рассчитаны на раскладку «папка на компонент» (`../Toggles/Toggles`, `../ContextMenu/ContextMenu`, `../ProgressRing/ProgressRing`, `../Button`). Если у вас иначе, поправьте импорты в начале файла.

## Быстрый старт

```tsx
type City = { id: number; name: string; country: string; population: number };

const columns: DataGridColumn<City>[] = [
  { id: "name", header: "Город", cell: (c) => c.name, width: 240 },
  { id: "country", header: "Страна", cell: (c) => c.country },
  { id: "population", header: "Население", cell: (c) => c.population, align: "end" },
];

<div style={{ height: 480 }}>
  <DataGrid rows={cities} columns={columns} getRowId={(c) => c.id} />
</div>
```

> **У таблицы должна быть высота.** По умолчанию она занимает `100%` высоты родителя. Если у родителя нет определённой высоты, таблица схлопнется до минимальных `160px`. Либо задайте родителю высоту, либо передайте `height`.

## Свойства

| Свойство | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `rows` | `readonly T[]` | — | Загруженные на данный момент строки |
| `columns` | `DataGridColumn<T>[]` | — | Описание колонок (ниже) |
| `getRowId` | `(row) => string \| number` | — | Стабильный уникальный id строки |
| `height` | `number \| string` | `"100%"` | Высота таблицы |
| `striped` | `boolean` | `false` | Чередующаяся заливка строк вместо разделителей |
| `emptyContent` | `ReactNode` | `"Нет данных"` | Что показать, когда строк нет |
| `selectable` | `boolean` | `false` | Колонка с чекбоксами |
| `selectedIds` | `ReadonlySet<id>` | — | Выделенные id (управляемый режим) |
| `defaultSelectedIds` | `Iterable<id>` | — | Выделенные id в начале (неуправляемый режим) |
| `onSelectionChange` | `(ids: ReadonlySet<id>) => void` | — | Выделение изменилось. Приходит новый `Set` |
| `onRowClick` | `(row) => void` | — | Клик по строке |
| `onRowActivate` | `(row) => void` | — | Двойной клик или Enter на строке |
| `hasMore` | `boolean` | `false` | На сервере есть ещё данные |
| `loadingMore` | `boolean` | `false` | Идёт подгрузка: в конце списка кольцо |
| `loadMoreError` | `boolean` | `false` | Подгрузка упала: сообщение и кнопка «Повторить» |
| `onEndReached` | `() => void` | — | Пора загрузить следующую порцию |
| `endReachedThreshold` | `number` | `10` | За сколько строк до конца вызывается `onEndReached` |
| `totalCount` | `number` | — | Всего строк на сервере, только для скринридеров |
| `resetKey` | `string \| number` | — | Смените, когда список заменён целиком (поиск, сортировка) |
| `rowMenu` | `(target) => ContextMenuItem[] \| null \| undefined` | — | Пункты контекстного меню строки |
| `animateChanges` | `boolean` | `true` | Анимировать появление и исчезновение строк |
| `className`, `style` | | | Корневой элемент |
| `aria-label`, `aria-labelledby` | | | Имя таблицы. Передайте одно из них |

`getRowId` читается при смене `rows`, а не при каждом рендере. Возвращаемый id должен быть уникальным и не меняться у той же записи: от него зависят выделение, курсор и анимации.

## Колонки

```ts
type DataGridColumn<T> = {
  id: string;                          // уникален в таблице
  header: ReactNode;                   // заголовок
  cell: (row: T, index: number) => ReactNode;
  width?: number;                      // начальная ширина, 160
  minWidth?: number;                   // 80
  maxWidth?: number;
  resizable?: boolean;                 // true
  align?: "start" | "center" | "end";  // выравнивание заголовка и ячеек
};
```

### Одна строка, обрезка

Высота строки одна и та же для всех (40px) и не настраивается: на ней держится виртуализация. Текст в ячейке не переносится, а обрезается многоточием. Многоточие работает для текста и строчных элементов. Если `cell` возвращает блочный элемент или `flex`-контейнер, ограничьте его ширину и обрежьте текст внутри него сами.

### Изменение ширины

- Мышью: потяните правый край заголовка. Линия-ручка появляется при наведении.
- С клавиатуры: Tab до ручки (у неё `role="separator"`), затем ← и → меняют ширину на 10px, с Shift на 50px.
- Ширина не выходит за `minWidth` и `maxWidth`.
- Таблица **помнит ширины, пока жива**. После повторного монтирования они вернутся к `width` из описания колонок. Сохранять их куда-либо таблица не умеет.
- Суммарная ширина больше окна: появляется горизонтальная прокрутка, шапка прокручивается вместе со строками. Меньше окна: свободное место забирает **последняя колонка**, `maxWidth` для неё при растяжении не действует.

Чтобы колонку нельзя было менять, поставьте `resizable: false`.

## Выделение

```tsx
const [selected, setSelected] = useState<ReadonlySet<number | string>>(new Set());

<DataGrid
  selectable
  selectedIds={selected}
  onSelectionChange={setSelected}
  ...
/>
```

- Колонка с чекбоксами выделяет строки. **Клик по самой строке выделения не меняет**, он вызывает только `onRowClick`.
- Shift+клик по чекбоксу выделяет диапазон от последней отмеченной строки.
- Чекбокс в шапке работает только с загруженными строками. Если выбрана часть, он в смешанном состоянии. Выделенные id, которых сейчас нет в `rows`, он не трогает.
- Таблица **не очищает** выделение, когда строки исчезают (например, поиск скрыл их): выделенные id хранит родитель. Это нужно, чтобы поиск не сбрасывал выбор. Лишние id при необходимости чистите сами.
- Без `selectedIds` выделением управляет сама таблица, а `onSelectionChange` всё равно вызывается.

## Бесконечная прокрутка

Страниц нет: родитель добавляет новые строки в конец `rows`, а таблица сообщает, когда это пора сделать.

```tsx
const [rows, setRows] = useState<City[]>([]);
const [hasMore, setHasMore] = useState(true);
const [loading, setLoading] = useState(false);
const [failed, setFailed] = useState(false);

const loadNext = async () => {
  setLoading(true);
  setFailed(false);
  try {
    const page = await api.getCities({ offset: rows.length, limit: 50 });
    setRows((r) => [...r, ...page.items]);
    setHasMore(page.hasMore);
  } catch {
    setFailed(true);
  } finally {
    setLoading(false);
  }
};

<DataGrid
  rows={rows}
  hasMore={hasMore}
  loadingMore={loading}
  loadMoreError={failed}
  onEndReached={loadNext}
  ...
/>
```

Как это работает:

- `onEndReached` вызывается, когда до конца загруженных строк остаётся не больше `endReachedThreshold` строк (по умолчанию 10) и при этом `hasMore` равен `true`, нет `loadingMore` и нет `loadMoreError`.
- **Первая загрузка тоже может идти через `onEndReached`:** если `rows` пуст, а `hasMore` равен `true`, таблица вызовет его сразу. Если первую порцию вы грузите иначе (например, в `Page` через `onNavigate`), передавайте `hasMore` уже после неё.
- **Короткий список:** если строк не хватает, чтобы заполнить высоту таблицы, а `hasMore` равен `true`, `onEndReached` вызывается сам. Иначе прокрутить было бы нечего.
- **Один вызов на каждое число загруженных строк.** Если сервер вернул пустую порцию при `hasMore: true`, повторного вызова не будет, цикла не получится. Поэтому, когда данные закончились, ставьте `hasMore: false`.
- Если пользователь в момент появления кольца или ошибки уже находится у самого низа, таблица сама прокручивает так, чтобы они были видны.
- `loadingMore`: в конце списка показывается `ProgressRing`. `loadMoreError`: сообщение «Не удалось загрузить данные.» и кнопка «Повторить», которая снова вызывает `onEndReached`.
- Пустое состояние (`emptyContent`) показывается только когда строк нет, нет `hasMore`, нет `loadingMore` и нет `loadMoreError`.
- Первая загрузка, общая ошибка и ожидание остаются на стороне родителя (например, `Page` с `onNavigate`). Таблица отвечает только за подгрузку в конце списка.

## Поиск и сортировка снаружи

Таблица их не делает. Родитель сам перезапрашивает данные и подставляет новые `rows`. Чтобы таблица поняла, что список заменён целиком, меняйте `resetKey`:

```tsx
<DataGrid
  rows={rows}
  resetKey={`${query}|${sortField}|${sortDir}`}
  ...
/>
```

При смене `resetKey` таблица прокручивается к началу, сбрасывает курсор, закрывает меню и **не анимирует** замену. Ширины колонок и выделение сохраняются.

Если `resetKey` не менять, замена всё равно произойдёт, но прокрутка останется на месте, а мелкие различия (меньше 21 строки) будут показаны как появление и исчезновение строк.

Стрелку сортировки таблица не рисует. Положите её в `header` колонки (это `ReactNode`) и повесьте обработчик там же.

## Появление и исчезновение строк

Таблица сравнивает новый `rows` с прежним по `id` и анимирует небольшие изменения:

| Событие | Что происходит |
| --- | --- |
| Вставка строки (в начало или в середину) | строка проявляется (~200мс), нижние строки съезжают, новая строка ~1.5с слегка подсвечена акцентным цветом |
| Удаление строки | строка тает на месте (~150мс), нижние строки съезжают вверх |
| Добавление в конец списка | **без анимации**: считается подгрузкой |
| Замена списка (`resetKey` изменился) | без анимации |
| Больше 20 добавленных и удалённых строк за раз | без анимации |
| Изменение данных в существующей строке | без анимации |
| `prefers-reduced-motion` | без движения, остаётся подсветка новой строки |

Дополнительно:

- **Вставка выше видимой области не сдвигает картинку.** Если пользователь прокрутил вниз, а сверху добавили или убрали строки, таблица сдвигает прокрутку так, чтобы строка в верхней части окна осталась на месте. В этом случае анимации нет. Если пользователь у самого верха, строки съезжают вниз с анимацией.
- Исчезающие строки анимируются, только если они были видны.
- Курсор на строке, которая исчезла, переходит на соседнюю. Контекстное меню исчезнувшей строки закрывается.
- Отключить всё это можно через `animateChanges={false}`.

Ограничение: живая запись, которая приходит в самый конец списка, неотличима от подгрузки и анимироваться не будет.

## Контекстное меню

```tsx
<DataGrid
  rowMenu={({ row, rows }) => [
    { id: "open", label: "Открыть", icon: <OpenIcon />, onSelect: () => open(row) },
    { id: "copy", label: "Копировать", hint: "Ctrl+C", onSelect: () => copy(rows) },
    { type: "separator" },
    { id: "delete", label: "Удалить", danger: true, onSelect: () => remove(rows) },
  ]}
  ...
/>
```

`rowMenu` получает `{ row, rows }`:

- `row` — строка, на которой открыли меню;
- `rows` — строки, к которым применяется команда: **все выделенные**, если строка выделена, иначе только `row`.

Как в файловом менеджере: правый клик по невыделенной строке **заменяет выделение** этой строкой (при `selectable`).

Если `rowMenu` вернул `null`, `undefined` или пустой список, меню не открывается, и остаётся обычное меню браузера. Пункты вычисляются в момент открытия.

Открытие:

- правая кнопка мыши;
- Shift+F10 или клавиша «Меню» на строке с курсором (меню появляется у строки, курсор сразу на первом доступном пункте).

Долгое нажатие на тач-экранах отдельно не обрабатывается.

### Пункты меню

```ts
type ContextMenuItem =
  | {
      id: string;            // уникален в меню
      label: ReactNode;
      icon?: ReactNode;      // 16×16; если есть хотя бы у одного пункта, под иконки выделяется колонка у всех
      hint?: string;         // подсказка (например, сочетание клавиш), только текст
      danger?: boolean;      // красный пункт
      disabled?: boolean;
      onSelect?: () => void; // вызывается после закрытия меню
    }
  | { type: "separator"; id?: string };
```

`hint` только отображается и клавиши не привязывает. Подменю нет.

### Компонент ContextMenu отдельно

`ContextMenu` можно использовать и вне таблицы. Монтируйте его, пока меню открыто, и размонтируйте в `onClose`:

```tsx
{menu && (
  <ContextMenu
    items={menu.items}
    x={menu.x}                       // clientX
    y={menu.y}                       // clientY
    activateFirst={menu.fromKeyboard}
    aria-label="Действия"
    onClose={(restoreFocus) => {
      setMenu(null);
      if (restoreFocus) triggerRef.current?.focus();
    }}
  />
)}
```

| Свойство | Тип | Описание |
| --- | --- | --- |
| `items` | `ContextMenuItem[]` | Пункты |
| `x`, `y` | `number` | Точка открытия в координатах окна |
| `onClose` | `(restoreFocus: boolean) => void` | Меню просит закрыться. `restoreFocus` равен `true`, если закрыли с клавиатуры или выбрали пункт: верните фокус туда, где он был. `false`, если кликнули в другом месте |
| `activateFirst` | `boolean` | Сразу поставить курсор на первый доступный пункт (для открытия с клавиатуры) |
| `aria-label` | `string` | Имя меню |
| `className` | `string` | Класс панели |

Поведение меню:

- Рендерится порталом в `<body>` с `position: fixed` и слоем `--ZIndexPopup`, поэтому его не обрезают родители с `overflow` и не портит `opacity` предков (важно для `backdrop-filter` стекла). Поверх `Modal` оно тоже видно.
- Если не помещается, разворачивается влево и/или вверх от точки и всегда остаётся в окне. Слишком высокое меню прокручивается.
- Клавиши: ↑ и ↓ (по кругу, недоступные пункты пропускаются), Home, End, Enter и Space выбирают, Esc и Tab закрывают. Esc сообщает вложенному `Modal`, что он не его (`preventDefault`).
- Закрывается кликом вне меню, прокруткой, изменением размера окна и уходом из окна. Прокрутка внутри самого меню его не закрывает.
- При выборе пункта фокус возвращается на таблицу **до** вызова `onSelect`. Поэтому `Modal`, открытый из `onSelect`, при закрытии вернёт фокус на таблицу.

## Клавиатура

Таблица — одна точка входа для Tab; строки не фокусируются по отдельности, курсор показан через `aria-activedescendant` и рамку (рамка видна только при фокусе с клавиатуры).

| Клавиша | Действие |
| --- | --- |
| ↑ / ↓ | Курсор на строку выше или ниже |
| PageUp / PageDown | Курсор на страницу вверх или вниз |
| Home / End | Первая или последняя загруженная строка |
| Space | Выделить или снять выделение (при `selectable`) |
| Enter | `onRowActivate` для строки с курсором |
| Ctrl+A / Cmd+A | Выделить все загруженные строки (при `selectable`) |
| Shift+F10 / «Меню» | Контекстное меню строки (если задан `rowMenu`) |

Строка с курсором всегда остаётся в DOM, даже если её прокрутили за пределы окна, поэтому курсор не теряется. Фокусируемы также ручки изменения ширины колонок (по одной на колонку), чтобы ширину можно было менять без мыши.

## Внешний вид

| Что | Значение |
| --- | --- |
| Высота строки и шапки | `40px`, не настраивается |
| Границы | нет; единственная линия — разделитель между строками (`--DividerStrokeColorDefaultBrush`) |
| `striped` | разделителей нет, нечётные строки залиты `--ControlFillColorDefaultBrush` |
| Шапка | закреплена сверху (`position: sticky`), непрозрачная, фон `--LayerFillColorDefaultBrush`, переопределяется `--DataGridHeaderBackground`; текст жирный, цвет `--TextFillColorSecondaryBrush` |
| Наведение на строку | `--ControlFillColorSecondaryBrush` |
| Выделенная строка | акцентная заливка (14%, при наведении 22%) и плашка 3×16 слева, как у выбранного пункта `ComboBox` |
| Курсор клавиатуры | рамка 2px `--AccentFillColorSelectedTextBackgroundBrush` внутри строки |
| Отступ в ячейке | `12px` по горизонтали |
| Колонка выделения | `48px` |
| Подгрузка | `ProgressRing` размером 20 по центру видимой области |
| Ошибка подгрузки | текст цветом `--SystemFillColorCriticalBrush` и кнопка «Повторить» |
| Пустая таблица | текст по центру под шапкой, цвет `--TextFillColorSecondaryBrush` |

Тексты «Нет данных» (можно заменить через `emptyContent`), «Не удалось загрузить данные.», «Повторить», «Загрузка», «Выбрать все строки», «Выбрать строку», «Изменить ширину колонки» и «Действия со строкой» вшиты в код.

## Доступность

- Таблица `role="grid"`, шапка и строки `role="row"`, ячейки `columnheader` и `gridcell`. Заданы `aria-rowcount` (по `totalCount`; если он не передан и есть `hasMore`, то `-1`, то есть «неизвестно»), `aria-colcount`, `aria-rowindex`, `aria-colindex`.
- При `selectable` стоят `aria-multiselectable` и `aria-selected` на строках.
- Курсор передаётся через `aria-activedescendant`.
- Ручка ширины: `role="separator"`, `aria-orientation="vertical"`, `aria-valuenow/min/max`.
- Блок подгрузки: `role="status"` (кольцо) и `role="alert"` (ошибка).
- Меню: `role="menu"`, `menuitem`, `separator`, `aria-disabled`, `aria-activedescendant`.
- Исчезающие «призраки» скрыты от скринридеров (`aria-hidden`).
- Передайте таблице `aria-label` или `aria-labelledby`.

## Ограничения

- Высота строки одна и не настраивается. Переноса текста в ячейках нет.
- Сортировки, поиска, фильтров, закрепления колонок, редактирования, постраничной навигации нет. Сортировка, поиск и фильтры делаются снаружи.
- Ширины колонок не сохраняются между монтированиями.
- Выделение по клику на строку не поддерживается, только через колонку с чекбоксами.
- Выделенные id, которых нет в `rows`, остаются в наборе: чистит их родитель.
- Анимации появления и исчезновения работают для небольших изменений (до 20 строк) и не для добавления в конец списка.
- Контекстное меню без подменю; долгое нажатие на тач-экранах отдельно не обрабатывается.
- Таблица не вызывает `onEndReached` для строк, которые не загружены: она знает только то, что в `rows`.
- Преломление стекла в меню работает только в Chromium (как у `GlassPanel`), в остальных браузерах используется размытие.
- Ручки ширины колонок добавляют по одной остановке Tab на колонку.
