# Page

Каркас страницы приложения: прилипающая шапка с заголовком, кнопкой «Назад» и панелью инструментов, а под ней тело страницы. Если передать `onNavigate`, страница сама покажет загрузку, содержимое или ошибку с кнопкой «Повторить».

Компонент использует `useNavigate` из `react-router-dom`, поэтому должен находиться внутри роутера (`<BrowserRouter>`, `<RouterProvider>` и т. п.).

Весь контент [NavigationView](./NavigationView.md) предполагается оформлять как `Page`. Внутри `NavigationView` страница сама выбирает, как появиться: свойством `transition` задаётся свой переход (см. [Переход при появлении](#переход-при-появлении)). Вне `NavigationView` страница работает так же, как раньше.

## Подключение

```
Page.tsx
Page.module.css
ProgressRing/       // ProgressRing.tsx и ProgressRing.module.css, см. ProgressRing.md
Button/
Toolbar/
NavigationView/pageTransitions.ts   // тип перехода и хук usePageTransition
index.css           // должен быть подключён в приложении: токены и классы типографики
```

```tsx
import Page from "./Page";
```

Компонент экспортируется как `export default`, тип свойств — `PageProps`.

> `Page.tsx` импортирует `../Button`, `../ProgressRing`, `../Toolbar` и `../NavigationView/pageTransitions`. Если у вас файлы лежат иначе, поправьте пути в импортах. Значок «Назад» нарисован внутри `Page.tsx`.

## Быстрый старт

```tsx
<Page title="Города">
  <CityList />
</Page>
```

С загрузкой данных:

```tsx
<Page
  title="Города"
  onNavigate={async () => {
    setCities(await api.getCities());
  }}
>
  <CityList cities={cities} />
</Page>
```

## Свойства

| Свойство | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `title` | `ReactNode` | — | Заголовок в шапке (стиль `SubtitleTextBlockStyle`, 20px) |
| `children` | `ReactNode` | — | Содержимое страницы |
| `showBackButton` | `boolean` | `false` | Показывать ли кнопку «Назад» слева в шапке |
| `onBack` | `() => void` | — | Дополнительный колбэк кнопки «Назад» (см. ниже) |
| `toolbar` | `Pick<ToolbarProps, "leading" \| "center" \| "trailing">` | — | Содержимое панели инструментов: слева, по центру, справа |
| `onNavigate` | `() => void \| Promise<void>` | — | Функция, которая выполняется при появлении страницы. Пока она работает, вместо содержимого показывается кольцо загрузки. Необязательная |
| `transition` | `PageTransitionSetting` | — | Переход, которым страница появляется внутри `NavigationView`: `"auto"`, `"entrance"`, `"drillIn"`, `"slide"`, `"suppress"` или функция. Без него действует `pageTransition` из `NavigationView`. Вне `NavigationView` не используется |

### Кнопка «Назад»

Кнопка с `aria-label="Назад"` сначала переходит на уровень выше по маршруту (`navigate("..", { relative: "route" })`), затем вызывает `onBack`, если он передан. То есть `onBack` — это дополнительное действие после перехода, а не замена перехода: отменить его через `onBack` нельзя.

Если задан `toolbar.leading`, он показывается сразу после кнопки «Назад».

## `onNavigate`: загрузка и ошибка

`onNavigate` — необязательная функция. Она может быть синхронной или асинхронной.

### Состояния

| Состояние | Когда | Что показывается в теле страницы |
| --- | --- | --- |
| Загрузка | пока `onNavigate` выполняется | только `ProgressRing`, без текста |
| Готово | `onNavigate` завершилась без ошибки или не передана | `children` |
| Ошибка | `onNavigate` бросила ошибку или вернула отклонённый промис | текст «Не удалось загрузить страницу.» и кнопка «Повторить» |

Шапка (заголовок, кнопка «Назад», панель инструментов) остаётся на месте во всех состояниях, поэтому пользователь может вернуться назад, даже если загрузка зависла или упала.

### Как это работает

1. Если `onNavigate` передан, страница сразу стартует в состоянии «Загрузка» (без мерцания содержимого) и вызывает функцию после появления на экране.
2. `children` во время загрузки и ошибки **не монтируются вовсе**. Они появляются только после успешного завершения.
3. Если функция завершилась без ошибки, показываются `children`.
4. Если функция бросила ошибку, она пишется в `console.error`, а в теле показывается сообщение и кнопка «Повторить».
5. «Повторить» снова переводит страницу в «Загрузку» и вызывает `onNavigate` ещё раз. Вызывается актуальная версия функции, переданная в последнем рендере.

### Что важно знать

- **Функция вызывается один раз при появлении страницы.** Новая ссылка на функцию на следующих рендерах (например, стрелка прямо в JSX) повторный вызов не запускает. Поэтому оборачивать её в `useCallback` не нужно.
- **Если страница остаётся смонтированной при смене данных** (например, меняется параметр маршрута `/cities/:id`, а React переиспользует тот же `Page`), `onNavigate` повторно не вызовется. Задайте `key`, чтобы страница пересоздавалась:

  ```tsx
  <Page key={id} title="Город" onNavigate={loadCity}>
  ```

- **Результат устаревших запусков игнорируется.** Если страница размонтирована до завершения функции, состояние не обновляется. Сам запрос при этом не отменяется: `onNavigate` не получает `AbortSignal`.
- **В режиме `React.StrictMode` в разработке функция вызывается дважды** (двойной запуск эффектов). Учитывайте это, если у неё есть побочные эффекты. В продакшене вызов один.
- **Ошибка пользователю не детализируется.** Текст сообщения фиксированный, подробности ошибки видны только в консоли. Если нужно показать причину, обработайте ошибку внутри `onNavigate` и обновите своё состояние, а наружу ничего не бросайте.
- **Данные передавайте через состояние.** `onNavigate` ничего не возвращает и значения в `children` не передаёт. Положите результат в состояние компонента-владельца (`setCities(...)`), а `children` читают его, как в примерах ниже.

## Переход при появлении

Внутри `NavigationView` у каждой страницы своя рамка, которая анимируется при появлении. `Page` сообщает рамке, каким переходом ему появиться:

```tsx
<Page title="Новая запись" showBackButton transition="slide">
  <Form />
</Page>
```

- Значения и порядок выбора: `transition` у `Page`, затем `pageTransition` у `NavigationView`, затем `"auto"`. Описание переходов и своих функций в [NavigationView.md](./NavigationView.md#переходы-между-страницами).
- Анимируется вся страница вместе с шапкой, а не только тело: кольцо загрузки (`onNavigate`) тоже выезжает вместе с ней.
- Тип `PageTransitionSetting` и хук `usePageTransition` лежат в `NavigationView/pageTransitions.ts`. Хук можно вызвать и в своей странице без `Page`, если у неё другая шапка.
- Настройка читается один раз, когда страница появилась вместе с рамкой. Страница, которая подгрузится позже (`React.lazy` с `Suspense`), своё `transition` не применит.
- Кнопка «Назад» делает `navigate("..")`, то есть переход на страницу выше по пути. Если `NavigationView` получает `pageKey={pathname}`, для него это возврат (`direction: "back"`), и `drillIn` сыграет в обратную сторону.

## Примеры

### 1. Простая страница без загрузки

```tsx
<Page title="Настройки">
  <Settings />
</Page>
```

Без `onNavigate` содержимое показывается сразу, как раньше.

### 2. Кнопка «Назад» и панель инструментов

```tsx
<Page
  title="Город"
  showBackButton
  onBack={() => analytics.track("city_back")}
  toolbar={{
    leading: <Button icon={<RefreshIcon />} aria-label="Обновить" />,
    trailing: <Button>Редактировать</Button>,
  }}
>
  <CityDetails />
</Page>
```

### 3. Загрузка данных страницы

```tsx
function CityPage() {
  const { id } = useParams();
  const [city, setCity] = useState<City | null>(null);

  return (
    <Page
      key={id}
      title="Город"
      showBackButton
      onNavigate={async () => {
        setCity(await api.getCity(id!));
      }}
    >
      {city && <CityDetails city={city} />}
    </Page>
  );
}
```

Пока идёт запрос, тело страницы занимает кольцо загрузки. После успеха показываются детали города. Если запрос упал, пользователь видит сообщение об ошибке и кнопку «Повторить», которая повторит тот же запрос.

Проверка `city &&` нужна только для типов TypeScript: к моменту показа `children` состояние уже заполнено.

### 4. Несколько запросов сразу

```tsx
<Page
  title="Дашборд"
  onNavigate={async () => {
    const [user, stats] = await Promise.all([api.getUser(), api.getStats()]);
    setUser(user);
    setStats(stats);
  }}
>
  <Dashboard user={user} stats={stats} />
</Page>
```

Ошибка любого из запросов переводит страницу в состояние ошибки, «Повторить» запускает обе загрузки заново.

### 5. Синхронная функция

```tsx
<Page title="Профиль" onNavigate={() => analytics.pageView("profile")}>
  <Profile />
</Page>
```

Синхронная функция завершается сразу, поэтому содержимое появится почти мгновенно, возможно, с кратким кадром загрузки.

### 6. Ошибка со своей причиной

Фиксированный текст ошибки заменить нельзя, но можно показывать свою причину внутри содержимого, если не бросать ошибку наружу:

```tsx
onNavigate={async () => {
  try {
    setCity(await api.getCity(id!));
  } catch (e) {
    setLoadError(e instanceof ApiError ? e.message : "Неизвестная ошибка");
    // ошибку не пробрасываем: страница считает загрузку завершённой
  }
}}
```

В таком случае кнопки «Повторить» от страницы не будет: повтор придётся сделать самостоятельно в своём содержимом.

### 7. Свой переход страницы

```tsx
// без анимации, например у страницы с тяжёлым содержимым
<Page title="Отчёт" transition="suppress">
  <Report />
</Page>

// своя функция: вглубь выезжает справа, остальное по умолчанию
<Page
  title="Запись"
  showBackButton
  transition={(info) => (info.relation === "child" ? "slide" : "auto")}
>
  <Form />
</Page>
```

## Внешний вид и размеры

| Что | Значение |
| --- | --- |
| Страница | `min-height: 100%`, `position: relative` |
| Шапка | `position: sticky; top: 0`, слой `z-index: 5`, отступы `16px 24px`, зазор `12px` |
| Фон шапки | градиент от `--LayerFillColorDefaultBrush` к прозрачному: содержимое плавно уходит под шапку при прокрутке |
| Тело | отступы `12px 24px` |
| Состояния загрузки и ошибки | блок по центру, минимальная высота `240px`, зазор `16px`, текст по центру |
| Кольцо загрузки | `ProgressRing`, размер `32`, `aria-label="Загрузка"` (текст не виден) |
| Сообщение об ошибке | `BodyTextBlockStyle`, цвет `--TextFillColorSecondaryBrush` |

Шапка закреплена относительно ближайшего прокручиваемого предка, поэтому `Page` нужно размещать в контейнере, который прокручивается. Внутри `NavigationView` такой контейнер есть: он создаётся для каждой страницы заново.

## Доступность

- Кнопка «Назад» имеет `aria-label="Назад"`.
- Кольцо загрузки имеет `role="progressbar"` и `aria-label="Загрузка"`.
- Блок ошибки имеет `role="alert"`, поэтому сообщение озвучивается сразу при появлении.
- Шапка остаётся доступной в любом состоянии.

## Ограничения

- Тексты «Назад», «Загрузка», «Не удалось загрузить страницу.» и «Повторить», а также запись в консоли вшиты в код и не настраиваются через свойства.
- `onNavigate` не получает `AbortSignal` и не может быть отменён.
- Функция вызывается только при появлении страницы, повторный запуск возможен лишь кнопкой «Повторить» или пересозданием страницы через `key`.
- Нет отдельного состояния «обновление»: при повторном запуске содержимое снова заменяется кольцом.
- `transition` действует только внутри `NavigationView` и только при появлении страницы. Переход при уходе страницы не настраивается: анимируется лишь новая страница.
